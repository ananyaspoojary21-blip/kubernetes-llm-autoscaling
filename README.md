# Autoscaling Lab

Autoscaling Lab is the workload and observation layer for a controlled Kubernetes autoscaling
study. It gives researchers a small Flask service that produces deterministic CPU pressure and a
React research console that makes each request inspectable.

## Research objective

The later study compares reactive Kubernetes HPA behavior with an explainable reasoning layer.
HPA will remain the actual scaling controller. Any future LLM layer will only observe metrics and
produce a shadow/advisory recommendation; it will never directly change Kubernetes replicas.

## Architecture

- `artifacts/autoscaling-lab` — React + TypeScript + Vite research console
- `backend` — independently runnable Python 3.11 + Flask workload service
- `backend/Dockerfile` — standalone container image for Docker Desktop

Kubernetes manifests, HPA, Prometheus, metrics-server, Grafana, Helm, Terraform, Argo CD, and
LLM integrations are intentionally outside this application layer.

## Run the backend

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate       # Windows
pip install -r requirements-dev.txt
python app.py
```

The API listens on `http://localhost:5000`. The console uses relative paths by default; set
`VITE_API_URL=http://localhost:5000` when the console and Flask service run on separate origins.

## Run the frontend

From the repository root:

```bash
pnpm install
pnpm --filter @workspace/autoscaling-lab run dev
```

## Docker

```bash
docker build -t kubernetes-autoscaling-demo ./backend
docker run --rm -p 5000:5000 kubernetes-autoscaling-demo
```

## API endpoints

`GET /`, `GET /health`, and `GET /info` expose service metadata. `GET /cpu?duration=10` runs a
CPU-only workload. `GET /work?duration=5` runs the same workload and adds hostname and request ID
metadata. Durations are bounded by `MAX_WORK_DURATION`, defaulting to 60 seconds.

## Later Kubernetes connection

The Flask container can later become a Kubernetes Deployment target. A future HPA can observe the
CPU generated by `/cpu` and `/work` and perform real scaling. Prometheus and an LLM advisor can be
added as observation systems later, but the advisor must remain shadow/advisory so experiment
control stays with Kubernetes HPA rather than an opaque application-side decision.
